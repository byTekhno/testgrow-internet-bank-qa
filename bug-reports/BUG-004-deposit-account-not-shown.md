# BUG-004 Депозитные счета не отображаются

**Статус:** New  
**Серьёзность:** Critical  
**Приоритет:** High  
**Модуль:** Список счетов · Перевод между счетами  
**Требование:** REQ01, REQ05, REQ13, REQ14, ИБ-1  
**Окружение:** Windows 11, Google Chrome, TestGrow practice99 — {TEST}GROW BANK  
**Дата:** 2026-08-30  
**Тест-кейсы:** TC-005, TC-007, TC-008, TC-031, TC-033 (Skipped)

## Шаги

1. Войти в модуль под **любым клиентом**, у которого в [test-data/clients.md](../test-data/clients.md) есть **депозитный** счёт.
2. **Список счетов:** открыть **«Счета»** и сравнить таблицу с тестовыми данными.
3. **Перевод:** открыть **«Перевод между счетами»**, выбрать «Со счёта», открыть **«На счёт»** и проверить наличие депозитных счетов (REQ05).
4. Повторить для других клиентов с депозитами.



## Ожидаемый результат

По **REQ01** депозитные счета **отображаются** в списке счетов наравне с другими допустимыми типами.

По **REQ05** депозитный счёт **доступен для зачисления** в списке «На счёт» при переводе.

По **REQ13–REQ14** все счета клиента (включая депозитные) присутствуют в таблице с корректными полями.

## Фактический результат

Депозитные счета **не отображаются** — дефект **системный**, воспроизводится у **всех проверенных клиентов** с депозитами.


| Проверка                       | Результат                          |
| ------------------------------ | ---------------------------------- |
| Все клиенты с депозитами       | Депозитные счета отсутствуют в UI  |
| ЭФ «Список счетов» (REQ01)     | Депозиты не показаны               |
| «На счёт» при переводе (REQ05) | Депозиты недоступны для зачисления |




### Пример 1 — единственный счёт депозитный (Тестов Олег Второй)

Список счетов **пустой** — таблица без строк. Депозит `42305810281317725013` не отображается.

Сообщение *«Счета отсутствуют…»* (ИБ-1, 3а) **не показано**.

### Пример 2 — текущий + депозитный (Рублев Николай Пятый)

В списке счетов виден только **Текущий** `40817810643921982053` (28 210,89 ₽).

**Депозитный** `42305810484831689001` (232 941,81 ₽) **отсутствует**.

### Пример 3 — перевод (TC-031, Рублев Николай Пятый)

При выбранном счёте списания в «На счёт» **нет депозитного** счёта — зачисление на депозит невозможно (REQ05).

## Влияние на тест-кейсы


| TC     | Статус  | Комментарий                                                          |
| ------ | ------- | -------------------------------------------------------------------- |
| TC-005 | Fail    | Депозитные счета не отображаются в списке (все клиенты с депозитами) |
| TC-007 | Fail    | Таблица неполная — депозиты отсутствуют                              |
| TC-008 | Fail    | Нет строки депозита для перехода к деталям (доп. к BUG-001)          |
| TC-009 | Skipped | У «Тестов Олег Второй» есть депозит в ТД, но UI пустой — см. BUG-004 |
| TC-031 | Fail    | Депозитный счёт недоступен в «На счёт» (REQ05)                       |
| TC-033 | Skipped | REQ03 не проверить: депозит скрыт BUG-004 (в «Со счёта» тоже нет)    |




## Дополнительно

- **REQ03** запрещает депозит только как счёт **списания** — это не должно скрывать его из списка счетов (REQ01) и из «На счёт» (REQ05).
- У клиента с **единственным** депозитом модуль «Счета» полностью неработоспособен.



## Примечание

Депозитный счёт допустим для отображения (REQ01) и для зачисления при переводе (REQ05). Системное скрытие депозитов — критический дефект данных клиента.
