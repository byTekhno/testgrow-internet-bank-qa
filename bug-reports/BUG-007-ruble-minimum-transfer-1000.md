# BUG-007 Минимальная сумма перевода 1 000 ₽ для рублёвых счетов (не в ТЗ)

**Статус:** New  
**Серьёзность:** Major  
**Приоритет:** Medium  
**Модуль:** Перевод между счетами  
**Требование:** REQ07, REQ09 (отсутствует в ТЗ)  
**Окружение:** Windows 11, Google Chrome, TestGrow practice99 — {TEST}GROW BANK  
**Дата:** 2026-08-30  

## Шаги

1. Войти под клиентом с **рублёвыми** счетами и достаточным остатком.
2. Открыть **«Перевод между счетами»**, выбрать два рублёвых счёта (разные типы).
3. Ввести сумму **999,00** или меньше (напр. `100,5`, `999,00`).
4. Проверить подсветку поля, текст превью и возможность перевода.
5. Для контроля повторить на **USD/EUR/CNY** — суммы **< 1 000** в валюте счёта.



## Ожидаемый результат

В **ТЗ** (`ibrequirements.md`) указаны только **максимальные** лимиты (REQ09). **Минимальная** сумма перевода **не описана**.

Ожидаемое поведение по ТЗ: при сумме, заполненной по маске REQ25, и достаточном остатке — перевод **должен быть возможен** (в т.ч. `0,01`, `999,00`).

## Фактический результат

**Только для рублёвых счетов** действует незадокументированное правило: минимальная сумма перевода **1 000,00 ₽**.

При вводе **999,00** и **меньше**:

- поле суммы **подсвечивается красным**;
- под формой **всё равно** отображается: *«Со счёта … будет списана сумма: …»*;
- перевод **невозможен**.

При сумме **≥ 1 000,00 ₽** перевод выполняется (с учётом других дефектов, напр. BUG-002).


| Сумма (RUB) | Подсветка | Превью «будет списана» | Перевод |
| ----------- | --------- | ---------------------- | ------- |
| ≤ 999,99    | Красная   | Показывается           | Нет     |
| ≥ 1 000,00  | Нет       | Показывается           | Да*     |


 при прочих валидных условиях

**Закономерность:** правило **только для RUB**; для USD, EUR, CNY и др. суммы **< 1 000** в валюте счёта **не блокируются** этим порогом.


| Валюта | Минимум 1 000 в валюте счёта                  |
| ------ | --------------------------------------------- |
| RUB    | **Да** — дефект / недокументированное правило |
| USD    | Нет (проверено)                               |
| EUR    | Нет (проверено)                               |
| CNY    | Нет (проверено)                               |




### Подтверждённый пример — 999 ₽


| Поле      | Значение                                         |
| --------- | ------------------------------------------------ |
| Клиент    | Тестов Николай Первый (или другой с RUB-счетами) |
| Со счёта  | `40817810253615964006` (Накопительный, Рубль)    |
| На счёт   | `40817810502758136001` (Текущий, Рубль)          |
| Ввод      | 999,00                                           |
| Подсветка | Красная                                          |
| Превью    | «Со счёта … будет списана сумма: **999,00**»     |
| Результат | Перевод **невозможен**                           |

## Дополнительно

- Минимум **1 000 ₽** **отсутствует** в REQ07, REQ08, REQ09.
- UX-дефект: при невалидной сумме показывается превью списания — вводит в заблуждение.
- Для **TC-036** (один знак после запятой) на RUB использовать **1 000,5** → `1 000,50`, а не `100,5`.



## Примечание

Если минимум 1 000 ₽ — задуманное бизнес-правило, его нужно добавить в ТЗ. До этого — расхождение реализации с документацией.
